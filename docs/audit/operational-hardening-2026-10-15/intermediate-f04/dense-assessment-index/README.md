# Scoped assessment-history index qualification

The same SQLite/generated PostgreSQL domain fixture constructs 32 WorkItems with one attestation criterion and 128 explicitly recorded assessments each (4,096 total); no proof is fabricated with SQL. The exact current-focal omission-count query selects one owner and returns 128. SQLite uses the new covering criterion_assessment_by_criterion index. Real PostgreSQL EXPLAIN (ANALYZE,BUFFERS,FORMAT JSON) uses that index for a scoped index-only scan. The before plan drops only this index inside a rolled-back fixture transaction; all persisted domain rows and the migration index remain intact. No planner option or timeout is relaxed.

The initial PostgreSQL plans measured 1.460 ms without versus 0.360 ms with the index. Race qualification limits VACUUM/ANALYZE to the two fixture tables (not unrelated test schemas) and measures 1.679 versus 0.145 ms, with the same count and index-only plan. These explain timings are diagnostic measurements, not stable production percentiles. Both adapters pass normal/race runs. Production read SQL is unchanged from the controlled aa7ccc3 comparison; this additional fixture closes the separate migration-0029 index-justification gate. Exact final source CI is still required.
