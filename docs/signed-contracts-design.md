## Signed execution and review persistence foundation (P03, partial)

Migration 0021 adds separate signed execution, checkpoint/submission, review case/authority and immutable signed-fact tables. Existing v1 tables and migration checksums remain unchanged. Separate ports prevent `delivered` from being written into the legacy execution table, whose original status constraint remains intact. A delivered execution is terminal; the Task stays `in_progress`. Its review authority has a different Principal, execution, fence and lease. Expired/revoked/inconclusive review releases the case to pending; approved/changes_requested/cancelled/superseded cases remain terminal.

Storage checks exact byte digests, sizes, identity/scope, immutable targets and CAS. It does not assert that a detached proof is verified. Application must verify the signature with the expected purpose, server identity, registry role and live credential policy before deriving any signed mutation. Canonical payload bytes and detached proof are stored together; no unsigned companion command or persisted `verified` flag is authoritative. Signing specifications do not contain their own digest.

Review participant history includes execution/correction Principals and configured separation groups. It does not establish organizational independence or prevent administrator-created Sybil identities. Existing deployment-wide Outcome independence remains a stronger additional gate.

The generated signed execution adapters reuse v1 execution storage mechanics with separate maps/tables and explicit signed bindings. `tools/signedgen/generate.py` runs before PostgreSQL generation; CI checks generated outputs. v2 SQL content/lease versions use exact decimal text in SQLite and NUMERIC(20,0) in PostgreSQL. Existing v1 fingerprints/wire representations remain unchanged.

Tests exercise delivery without Task completion, terminal rejection, independent review, exact expiry, fenced takeover without TTL extension, immutable submission/spec/policy/round, rollback, unique open case, scoped pages/active counts, signed bytes across actual PostgreSQL clean restore and embedded unsigned task/assessment/parent completion bypasses. This foundation does not yet expose signed acquisition/return/review commands, configure persistent server trust, activate a Namespace or install workspace schema 2. Those are remaining implementation gates, not available features.


## Persistent issuer and issuance (P03 second part, in progress)

Migration 0022 pins one immutable instance Server ID, issuer-key ID/public key/fingerprint and creation time; it contains no signing secret. `WOS_SERVER_SIGNING_SEED_ENV` names the environment variable containing the canonical base64 32-byte seed. Startup in scoped API-token mode loads this secret into a local, IO-free Ed25519 signer, pins or checks the stored public identity and refuses silent key replacement. `WOS_SIGNED_ACCEPTANCE_FLOOR` configures direct/independent_review; the existing independent-review deployment flag remains stronger. An omitted signer supports existing unsigned deployments and public historical metadata; a configured missing/mismatched seed fails explicitly.

Migration 0023 recreates only Namespace protocol coordination metadata to expand its constraints, copying every old row/JSON byte unchanged. Its original table name is retained so existing 0.2 writers read epoch 2 and reject unsupported phases. It does not automatically activate a Namespace or prove older writers/DB credentials have been retired. Public activation is still forbidden until P10 validates all cutover gates.

Signed acquisition uses the same Application readiness/scope/domain rules with an authenticated credential even through trusted embedded composition. The Namespace guard serializes quota-sensitive acquisitions across Outcomes. Each acquisition has an independent idempotency intent, registered agent key, explicit current credential policy and the strongest deployment/Namespace/Outcome/Task/credential floor. The spec's exact signed digest is separate from the unchanged legacy semantic snapshot digest. New signed specification and material DTOs quote uint64 revisions; v2 submission digests cannot collapse adjacent counters through numeric canonicalization. v1 fingerprints remain unchanged.

Renewal verifies the exact persisted signed grant and live source credential/key policy, preserves the signed spec and issues a separate new authority. Takeover rotates execution/fence and changes the lease CAS without extending expiry. Fixed issuer/spec/latest-grant IDs avoid scanning unbounded renewal history. Immutable historical public keys verify old issuance; current issuer/agent status and policy authorize new operations. Current policy hardening appears in renewed grants and must also be rechecked on delivery. No `verified` caller flag grants authority.
