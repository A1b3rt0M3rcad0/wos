# E16 — Apply scope and composed requirements in the transaction

Implementation commit: `1d951c01e14bd761cfc55699c225dfb3d2746a00` (`fix(auth): E16 enforce scoped composite authorization atomically`).

The command pipeline now resolves all payload-dependent rights from the exact authorization catalog and checks the full set before receipt replay or writes. Plan creation uses `objective:create`, `task:create`, and `criterion:define` as applicable instead of broad legacy rights. Issue and Blocker compounds require both creation or resolution permissions, including multi-item variants. Signed execution returns, approved review returns, and `SyncWorkContract` add the documentary-record, assessment, waiver, direct completion, and conclusion permissions their effects actually use.

For signed `auto` returns, authorization before replay follows the durable acceptance receipt's disposition. A direct completion replay retains the completion permissions required by the original acceptance even if the live acceptance floor later tightens; a delivery for independent review does not gain completion rights it never used. The receipt is bound to the current namespace, Outcome, contract, Task, request ID, idempotency key, request digest, and accepted disposition. Unknown or inconsistent persisted results fail closed. A regression test revokes `task:accept` after a direct signed acceptance and confirms that replay is denied without changing revisions, events, or receipts.

Dependency change batches now derive each removed relation's source from the persisted Relation and validate source versions, Outcome revision, lifecycle, contract guards, and graph constraints in the same transaction before writing. The client cannot present the target endpoint as a forged source. Cross-Outcome Issue/Blocker owners and targets and documentary links, artifacts, and decisions are also rejected without partial records or receipts.
