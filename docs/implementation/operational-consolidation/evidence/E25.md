# E25 — Protect receipts, recovery, and intervention

**Status:** verified on 2026-10-21.  
**Commit:** [`bec3f4f`](https://github.com/A1b3rt0M3rcad0/wos/commit/bec3f4f8556bb2eabc8f75876972f4ef0257d55d).  
**Migration:** SQLite and PostgreSQL `0043_credential_bound_idempotency_receipts.sql`.

Protected lease-operation idempotency receipts now retain the canonical root
credential that authorized the mutation. Administrative contract revocation
records the issuer credential rather than comparing the issuer with the holder.
An authenticated replay cannot disclose an old unbound receipt; trusted embedded
replay remains compatible. The change preserves exact request fingerprints and
keeps signed-v2 receipts on their existing protocol.

The recovery tests cover same-root sessions, different credential roots for one
Principal, replay after restart, concurrent expired-lease reclaim with one fence
winner, and revocation racing with renew. SQLite and generated PostgreSQL use the
same migration and repository contract.
