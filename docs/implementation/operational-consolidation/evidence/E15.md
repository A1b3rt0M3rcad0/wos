# E15 — Introduce granular permissions and coherent limits

Implementation commit: `d72e216` (`feat(auth): E15 add granular operational permissions`).

The authorization catalog now has one source of truth in `domain/permission_catalog.go`; `Permission.Valid()` and `AllPermissions()` derive from it. Existing permission names remain recognized as exact values. New explicit capabilities cover Objective and Task planning, execution, review and acceptance, criteria, dependencies, Issues, Blockers, credentials, grants and policy administration. Command and security-administration authorization use exact operation mappings. Signed work/review operations retain their existing contract, signature and protocol permissions alongside the granular decision rights.

Grant and CredentialPolicy permission lists reject unknown values and duplicates, treat empty lists as deny-all, and enforce the 128-item maximum. The limit is reflected in API schemas. Permission labels/descriptions and command exposure metadata are centralized in the web assets. Bootstrap continues to assign its explicit full permission set.

Focused tests cover catalog single-source behavior, allow/deny isolation between `task:claim` and `task:accept`, empty/duplicate/unknown lists, the 128/129 boundary, and composite permission requirements. Signed authorization fixtures now include the granular permissions required by the command while retaining the established signed protocol authority.
