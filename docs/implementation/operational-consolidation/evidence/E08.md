# E08 — Gate all acquisition and readiness paths

Implementation commit: `f36bbe11e107e62b037dfb9639e44383df11c0b0`.

Claim and Reclaim, unsigned contract acquisition, and signed execution-contract
renew/resume now evaluate the shared Task readiness gate while holding the
Outcome coordination guard. A denied operation does not alter Task authority,
lifecycle, Outcome revision, domain events, or failure receipts. Existing
signed and unsigned ID/Next acquisition paths use the same evaluator; ready-work
now locks before reading its snapshot and reports only eligible Tasks. Detailed
contract views retain structured readiness reasons.

Next searches intentionally persist an idempotent receipt even when no candidate
is eligible. Tests confirm that a Task under a Planned Objective is skipped,
the search leaves operational state unchanged, and replay does not create a
second receipt.

Validation passed:

- Focused application and SQLite-package tests for Claim, Reclaim, unsigned
  contract acquisition, signed ID/Next acquisition, unsigned Next, ready and
  available work, detailed contract readiness, and Next replay.
- `git diff --check`.

The ready-work query still scans all Tasks and currently re-evaluates full
Objective, relation, and blocker state per Task. This is correct for the gate
but is not yet performance-qualified at large Outcome sizes; consolidate the
read snapshot before scaling this query, tracked for later query/qualification
work.

Not run: live PostgreSQL acquisition/concurrency integration; end-to-end
HTTP/MCP/CLI parity is E13.
