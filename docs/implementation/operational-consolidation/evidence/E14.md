# E14 — Use an explicit command authorization registry

Implementation commit: `58ef02f62134f4135e45c87f610e5e33a4440830`.

Substring-based permission inference has been removed. An exact-name registry covers every public command (111 descriptors) and the existing application-only commands; unregistered names fail closed. Existing primary permissions are preserved. Payload-dependent requirements for plan creation, initial Task criteria, and waived assessments are centralized and checked inside the command transaction before idempotency replay.

Command metadata now resolves Namespace, Scope, and Owner through registered resolvers. Signed work/review returns derive their scope only from the signed envelope binding, and inconsistent Scope/Owner values are rejected. The HTTP command catalog can expose the same requirements to presentation code without duplicating authorization tables.

Focused registry, type mismatch, conditional composition, Scope/Owner, signed-envelope, replay, and public command exposure tests passed. Application/commands builds and `git diff --check` passed.

Not run: full HTTP/MCP transport suites (dependency proxy HTTP 403); granular policy matrix is E15/E16.
