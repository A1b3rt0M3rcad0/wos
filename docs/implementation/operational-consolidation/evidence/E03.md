# E03 — Operational characterization fixtures

## Outcome

Added reusable Application and browser fixtures that create current WOS records
through supported commands/use cases: active Outcomes; planned, active,
achieved, and cancelled Objectives; Tasks across the persisted lifecycle; hard
and advisory dependencies; Objective-owned Issues; direct and subtree
Blockers; linked Evidence; and same-Principal versus independent Principal
credentials. A domain characterization test records the existing compatibility
behavior that permits Objective achievement from `planned`; it does not claim
the future `operational_v2` gate.

Protocol-specific bootstrap remains in each real integration journey. The
shared fixture does not pretend to configure `contracts_v1` or signed-v2 and
does not invent a pending delivery, signature, review case, key, receipt, or
credential. The existing contract browser journey and signed browser journeys
continue exercising genuine submissions and review. Their stale Task setup was
updated to use the required Objective owner, and the signed browser journey now
opens the Task Board from its Objective instead of selecting a removed
cross-context control.
