# E07 — Shared Objective and Task execution gates

Implementation commit: `321e2d9fbc6f44f0a6152e8fdc1302226548440a`.

Centralized read-only readiness evaluation for Objective execution, Task
activation, and Task acquisition. Readiness now separates authored definition,
scope eligibility, and exclusive authority while preserving the existing JSON
shape. Operational-v2 gates require an active Outcome, an in-progress owning
Objective and applicable ancestors, a complete Objective hierarchy, and no
applicable Blocker. Acquisition additionally retains dependency, schedule,
lifecycle, and live-lease checks. Compatibility-v1 keeps its historical
readiness rules; unknown profiles fail closed.

Stable reason codes and same-Outcome related references are included in
structured command errors. Recovery and observation remain separate from
advancing work. Objective start-definition checks and Task activation-definition
checks are now independent from lifecycle and scope predicates.

Validation passed:

- `go test ./packages/wos-core/application ./packages/wos-core/domain -count=1`.
- `go vet ./packages/wos-core/application ./packages/wos-core/domain`.
- `git diff --check`.
- Tests cover profile compatibility, parent and ancestor lifecycle, missing,
  cyclic and corrupt ancestry, Outcome state, Blockers, dependencies, schedule,
  authority, and read-only evaluation.

The gates are not yet wired into every acquisition or activation path; those
are E08 and E09. Full transport parity and browser behavior are later stages.
