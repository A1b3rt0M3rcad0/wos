# E09 — Gate activation and direct To Do creation

Implementation commit: `7680bbfb8a6563e4f9b2bac42e4fd4a1712a69f9`.

In `operational_v2`, activating a Backlog Task and creating a Task directly in
To Do now require an active, non-archived Outcome; a valid owning Objective and
in-progress ancestors; a complete Task definition with an active required
Criterion; and no applicable Blocker. Backlog creation remains available while
an Objective is Planned. `compatibility_v1` preserves the historical behavior.

Direct To Do creation validates the complete Task after its initial Criteria
have been assembled, inside the same UnitOfWork. Rejection rolls back the Task
and its initial Criteria. Workspace capabilities use the same activation gate
and expose its structured reason and remedy.

- Focused application tests for valid and denied activation, direct To Do
  creation, Backlog preservation, incomplete definitions, Planned owners and
  ancestors, archived/terminal Outcomes, capability parity, legacy-profile
  behavior, and no partial revisions/events/receipts.
- `git diff --check` and `gofmt` check.
