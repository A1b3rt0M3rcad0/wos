# E11 — Guard hierarchical reopen and cancellation

Implementation commit: `8af169be72c6b9ede205ddea0aa4ed360d55b7e1`.

In `operational_v2`, reopening a Task now requires an active Outcome and an active owner Objective and ancestor chain. `compatibility_v1` retains its historical reopen behavior. Reopening an Objective returns it to Planned, advances its completion cycle, and preserves its prior Conclusion in history; it does not start or achieve the Objective implicitly.

Objective cancellation reads a complete bounded structure under the Outcome coordination lock and fails closed if the hierarchy is incomplete or exceeds the limit. It blocks cancellation when descendant Objectives or Tasks remain active, leased, under a contract, or awaiting review. Recovery remains explicit: release/revoke/cancel the affected work before cancelling the Objective. An expired lease is not active authority, but an In Progress Task still blocks because expiry does not change its lifecycle.

Eight focused lifecycle tests passed, covering v2 ancestry, v1 compatibility, conclusion history/cycles, active descendant guards, lease release, nested work/review references, structural overflow, and cancellation/acquisition concurrency. `git diff --check` passed.

Not run: live SQL adapter concurrency and E11 transport parity.
