# E10 — Reject hierarchy dependency deadlocks

Implementation commit: `f46fa26`.

Hard Task-to-own-Objective dependencies remain rejected in every profile. In
`operational_v2`, new hard dependencies are also checked against Objective
ancestry so Tasks cannot wait for an ancestor that gates their execution and
Objectives cannot wait on descendant work that cannot start until the source
Objective is active. The checks cover direct additions, final dependency
batches, Task moves, and Objective reparenting. Advisory relations stay
informational. Incomplete or oversized hierarchy snapshots fail closed, while
`compatibility_v1` retains the prior ancestor/descendant behavior.

The dependency graph read/validate/write sequence is serialized by the Outcome
coordination lock. Rejected changes preserve relations, versions, events, and
Outcome revision. Placement previews report the same structured deadlock
reason and entity path as the write.

Validation passed:

- Full application suite: `go test ./packages/wos-core/application -count=1 -timeout=120s`.
- Focused hierarchy, batch, advisory, compatibility, movement, reparenting,
  and concurrent opposing-edge scenarios.
- `gofmt -d` and `git diff --check`.

Not run: live SQLite/PostgreSQL transaction-level concurrency, HTTP/MCP/SDK/CLI
parity, and large-Outcome query-cost qualification. Those remain later plan
stages.
