# E06 — Explicit operational profile migration

Implementation commit: `4fb1f247ffe134ad662b675328e9ebba9dca5a02`.

Added an authorized, read-only migration preview for one Outcome and a narrow
idempotent configuration command. The command requires a namespace administrator,
the expected Outcome version and Outcome revision (including an explicit zero),
a reason, and an idempotency key. It can only migrate
`compatibility_v1` to `operational_v2` with `strict_work`. It does not change
Objective completion modes, ownership, criteria, lifecycles, Tasks, or evidence.
Existing active or unresolved execution/review authority blocks migration with
referenced findings and remedies. The operation records a durable event with
the reason and expected revision.

The preview reads the revision and all audited facts from one serializable UOW
snapshot through the read repository. It does not acquire the Outcome write
guard, mutate coordination state, append events, or reserve an idempotency
receipt. The acceptance audit utility uses SQLite read-only/query-only mode or
a PostgreSQL repeatable-read read-only transaction and produces a versioned
JSON report.

Validation passed:

- `go test ./packages/wos-core/application ./packages/wos-core/domain -count=1`.
- `go vet ./packages/wos-core/application ./packages/wos-core/domain`.
- Focused migration tests cover authorization, a no-write preview, stale
  versions/revisions, revision zero, missing reason/revision, lease and active
  contract conflicts, rollback, unchanged Objective/Task state, durable event
  payload, and idempotent replay.
- The preview ran through the SQLite and PostgreSQL adapters against schema 37.
- `operational_profile_audit.py` produced valid read-only reports for populated
  SQLite and PostgreSQL schema-37 databases; both reported one eligible Outcome.
- `python3 -m py_compile`, `--help`, and `git diff --check` passed.
