# E04 — Operational and Objective completion policy types

## Outcome

Added `OperationalProfile` (`compatibility_v1`, `operational_v2`) to Outcome
and `ObjectiveCompletionMode` (`manual`, `automatic`) plus monotonic
`CompletionCycle` to Objective. Omitted legacy fields resolve to
`compatibility_v1`, `manual`, and cycle 1. Automatic completion is accepted
only with `operational_v2` and `strict_work`; Outcome acceptance remains a
separate explicit operation. Reopening increments the cycle, preserves the
Conclusion in history, clears the current Conclusion, and returns to Planned.
Counter and aggregate-version overflow fail before mutation.

Zero-valued new fields preserve the exact JSON bytes produced by the
pre-change aggregate shapes. Non-zero profiles/modes and large cycle values
round-trip through JSON. Existing command and signed-payload structs were not
changed, so the new aggregate fields do not enter old command fingerprints or
signed material.

E04 only defines and validates domain types. SQL persistence, enforcing
cross-aggregate configuration at repository boundaries, and exposing a
writable policy operation are later stages; no automatic completion is
enabled by this commit.
