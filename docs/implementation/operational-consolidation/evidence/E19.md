# E19 — Issue constrained credentials atomically

- Baseline/head before: `188c05e` (`docs(wos): record E17 and E18 evidence`).
- Implementation commit: `f83cd3f668eefce458c3bdeb3f3a8b5ff0089051`.
- Profile/protocol/database: namespace security administration; existing HTTP and MCP administrative commands; Memory and SQLite executed, generated PostgreSQL compiled.
- Files changed: credential issuance and security administration in Application/ports; Memory, SQLite and generated PostgreSQL adapters; migration `0039_credential_management.sql`; existing REST/OpenAPI command contract; version-bound fixtures; PostgreSQL generator.
- Behavior implemented: create a credential, frozen permission policy, safe issuance metadata, audit entry and idempotency receipt in one atomic administration operation. The generated bearer token is hash-only in storage and is returned only on the first response. Replays return safe credential metadata without returning the token.
- Policy behavior: permission templates/custom lists are materialized at issuance and intersected with the target Principal's Namespace grant. When selection is omitted, the current grant is frozen as a custom policy. An empty Outcome allowlist remains unrestricted within the frozen permissions; an empty signing-key allowlist permits no signing key. OpenAPI now documents that distinction.
- Recovery behavior: authorized retries check the durable receipt before re-reading mutable target grants or generating a new secret. A matching retry can recover the credential ID for explicit revocation after the target grant changes; caller permission, credential/session status, actor delegation and fingerprint are still checked.
- Requirements and scenarios covered: invalid or cross-scope issuance fails without a receipt; metadata insert failure rolls back credential, policy, audit, Namespace version and receipt; issue-only authority can issue; policy and metadata persist together; replay does not duplicate issuance or reveal token/digest; target-grant changes do not make a committed issuance receipt unrecoverable; the old REST route accepts and replays issuance metadata.
