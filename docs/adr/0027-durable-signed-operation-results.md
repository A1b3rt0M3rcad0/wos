# ADR-0027 — Durable signed operation results

Status: accepted for implementation, 2026-10-09.

P08 extends ADR-0025: an absent or expired short idempotency entry is not evidence that a signed acquisition, renewal, takeover or final return failed. Append one immutable accepted command result in the domain transaction, after domain effects/events/outbox and before commit. Key it by Namespace, authenticated Principal and idempotency intention; bind exact Outcome, CredentialID, command name, normalized command fingerprint and original command ID/revision. Different commands, payloads, scopes or credentials cannot reuse that intention.

Use the shared Application pipeline and an additive public Core port. SQLite/PostgreSQL migration 0025 and Memory implement the same contract. Historical v1 commands, encoding and fingerprints are unchanged. Original responses are bounded to 1 MiB and contain public issued documents/results, never private keys or API credentials. Keeping the original response rather than rebuilding from current state preserves original CAS values, grant/fencing and expiry after renewal or takeover. No replay acquires, extends, compensates or emits another domain event. This is accepted operational state, not a second event-sourcing log or agent runtime.

Replay reauthorizes the live credential, policy, scope and command in the transaction at authoritative time. Acquisition/renewal/takeover also recheck the selected agent key before replay. Accepted historical return receipts can remain readable after key retirement; replaying their public receipt cannot create new execution authority. A replacement CredentialID cannot impersonate the original accepted intention even under the same Principal. Storage remains trusted infrastructure; clients verify issuer envelopes before treating them as proof and obtain fresh focal metadata before acting.

The `operation` focal query exposes only the authenticated Principal and original CredentialID's result in the exact currently permitted Outcome. It is a bounded base64 expansion for harness reconciliation, with original command ID and response digest. It is not an agent's initial context or a claim that the original grant is still current. Historical signed specs/grants remain independently verifiable.

Durable results have retention/storage cost, especially during frequent lease renewal: public spec/work snapshots can repeat. This wave favors exact replay correctness; do not add a time-based purge that destroys unknown-response recovery. P12 must measure storage growth and bounded response cost. A future compact/deduplicated representation must reproduce the original response and proof bytes, CAS values and expiration; rebuilding from latest mutable state is insufficient.

Verification includes SQL cache expiry, an adapter that makes all short-cache calls fail, immutable original acquisition after renewal/takeover, cross-command/payload/CID rejection, live bearer revocation and clean SQLite/PostgreSQL restore. Native Windows and the complete operational workspace remain separate P08/P12 gates.


Pre-P08 signed cache results still present in storage, including expired entries, are read before the short cache can delete them. Their original CID/scope comes from the trusted original execution/review contract or accepted receipt's immutable target, never the replacement caller. Authenticated replay promotes them once into durable state without another domain event. Read-only operation expansion can inspect such an entry without writing. Ambiguous old keys used for multiple signed command names fail explicitly. Unsupported old signed administrative cache results require explicit scoped reconciliation. If an old writer already deleted all correlation data, do not fabricate a historical intention; preserve local pending state for explicit reconciliation. Retire old writers during P10 cutover.

P10 also persists authenticated `SetNamespaceWorkProtocol` intentions for the signed drain/activation phases. Current Namespace administration and the original live CredentialID are required; no agent key/policy is invented to authorize activation. The original exact CAS, writer acknowledgement and response survive loss of the short cache. Existing v1 protocol commands retain their historical cache and encoding behavior.
